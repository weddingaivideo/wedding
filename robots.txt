# WeddingAI.video — robots.txt (v1.1, 2026-08-04)
#
# Allows all well-behaved crawlers, blocks internal/recon paths, and
# declares every sitemap for fast discovery. Cloudflare Pages serves
# this file at the edge; no middleware touch.
#
# === IMPORTANT: Cloudflare Managed Content auto-injection ===
# Cloudflare's zone-level "Crawler Hints → Add Cloudflare's robots.txt template"
# feature PREPENDS a managed block to this file at the edge. The managed
# block contains `User-agent: *` with Content-Signal plus a per-bot
# `User-agent: ClaudeBot/GPTBot/... Disallow: /` list, which CONFLICTS
# with the explicit `User-agent: ClaudeBot Allow: /` rules below.
#
# Per RFC 9309 §2.2.2, the most-specific User-agent group wins, so our
# per-bot Allow: / rules in this file should override CF's per-bot
# Disallow: / from the prepended block. But parser behavior varies —
# Google uses first-match, Yandex uses longest-match, others use
# last-match within a specificity tier. This creates a real ambiguity
# (audit finding, 2026-08-04, "中" risk).
#
# RECOMMENDED ACTION (one-time, ~30s, can't be done from code):
#   Cloudflare Dashboard → weddingai.video → SEO → Crawler Hints
#     → "Add Cloudflare's robots.txt template to your existing robots.txt"
#     → Toggle OFF
# After that, this file becomes the sole source of truth and the
# ClaudeBot/GPTBot/etc. Disallow: / from CF will no longer appear in
# the served file. Our explicit per-bot Allow: / rules below then
# unambiguously apply.
#
# Disallow rules mirror _redirects 404 rules + .assetsignore. Single
# source of truth: this file + _redirects + .assetsignore should never
# disagree. If you add a new internal directory, update all three.
#
# Last reviewed: 2026-08-04 (Mavis audit pass 2)
